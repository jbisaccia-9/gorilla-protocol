# Pixel Streaming 2 Hosting

This directory prepares Gorilla Protocol for Epic's UE5.8 Pixel Streaming 2
stack. Epic supplies the Unreal plugin, browser frontend, and reference signaling
software; Epic does not run a public game host for this repository.

The production path is:

1. Package the Unreal project for Windows or Linux on a machine with UE5.8.
2. Allocate a paid GPU host with hardware video encoding.
3. Point a DNS name at that host and open the required firewall ports.
4. Run the HTTPS, signaling, STUN, and TURN stack from this directory.
5. Launch the packaged game against the private signaling WebSocket.
6. Link the README Play Now badge to the resulting HTTPS address.

## Included

- `PixelStreaming2` enabled in `GorillaProtocol.uproject`
- Epic Pixel Streaming Infrastructure pinned to the reviewed UE5.8 commit
  `d063f92e69750bc2eafd7e88011444cfddef1cbf`
- Wilbur signaling and Epic's browser player on private port `8080`
- Caddy HTTPS termination on public ports `80` and `443`
- CoTURN on `3478` with a restricted UDP relay range
- Per-connection, time-limited TURN credentials generated by Wilbur
- Single connected player per game instance
- Linux and Windows streamer launch scripts with offscreen rendering
- A latency-oriented 1280x720, 60 FPS profile with explicit NVENC H.264 CBR,
  adaptive WebRTC bitrate capped at 8 Mbps, and frame-rate-first degradation
- Linux systemd services that restart the streamer after a VM start
- Automatic power-off after ten minutes without a connected player
- A two-hour hard runtime limit per VM boot
- No committed cloud credentials, TLS keys, TURN secrets, or API tokens

Epic deprecated its old matchmaker as a scaling foundation. This setup therefore
deploys one private Unreal process for one active player. Autoscaling multiple
players requires a provider-specific allocator and is intentionally not faked by
this repository.

## GPU Host Requirements

- Ubuntu 24.04 x86_64 or Windows Server 2022
- Supported NVIDIA GPU and driver with hardware H.264 encoding
- Docker Engine with Compose for the Linux reference stack
- A public static IPv4 address; custom DNS is optional
- A packaged Gorilla Protocol build produced by UE5.8
- At least 16 GB RAM for the graybox; production assets will require more

Public firewall rules for the single-host baseline:

| Port | Protocol | Purpose |
|---|---|---|
| `80`, `443` | TCP | HTTPS player and certificate issuance |
| `3478` | TCP/UDP | STUN/TURN negotiation and fallback |
| `49160-49200` | UDP | TURN media relay range |

Do not expose `8080` or `8888` publicly. The game connects to signaling through
`ws://127.0.0.1:8888`; Caddy alone exposes the player endpoint.

## Prepare And Start

For the guarded Google Cloud deployment, including quota checks, current cost
boundaries, private administration, GPU driver setup, stop controls, and complete
teardown, see [`gcp/README.md`](gcp/README.md).

On the Linux GPU host:

```bash
cp Hosting/.env.example Hosting/.env
# Edit STREAM_DOMAIN, PUBLIC_IP, and GAME_BINARY.
./Hosting/bin/prepare_host.sh
./Hosting/bin/start_stack.sh
./Hosting/bin/start_streamer_linux.sh
```

`prepare_host.sh` downloads only the pinned official Epic commit and generates a
local TURN secret under `Hosting/runtime/`. Both `Hosting/.env` and the complete
runtime directory are Git-ignored.

The default 720p stream profile keeps enough GPU headroom for a stable 60 FPS
game render and uses H.264 CBR so UE routes video through the NVIDIA hardware
encoder instead of a high-latency VP8 fallback. Tune `STREAM_WIDTH`,
`STREAM_HEIGHT`, `STREAM_FPS`, and the three bitrate values in `Hosting/.env`
only after measuring a real browser session. Epic documents these options in the
[Pixel Streaming reference](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-pixel-streaming-reference?lang=en-US).

Validate the public endpoint with:

```bash
./Hosting/bin/healthcheck.sh
```

On Windows, run Epic's Wilbur server and CoTURN using the same settings, then
start the packaged game with:

```powershell
.\Hosting\bin\start_streamer_windows.ps1 `
  -GameExecutable "C:\GorillaProtocol\GorillaProtocol.exe"
```

## Packaging

Linux and Windows packaging commands are provided in `Scripts/package_linux.sh`
and `Scripts/package_windows.ps1`. Both refuse to package until the boot map has
been generated and committed. Use `Scripts/bootstrap_project.sh` on macOS/Linux
or `Scripts/bootstrap_project.ps1` on Windows to create it.

## Deployment Inputs

The repository cannot invent or charge these resources:

- GPU cloud provider, region, instance quota, and billing authorization
- Public IPv4 address
- DNS name and permission to modify its record
- UE5.8 installation and a successfully packaged game artifact

The guarded Google Cloud setup currently supplies these inputs for the public
demo. A newly packaged Linux build must still be uploaded whenever Unreal source
changes should appear in the browser; host-script changes can be deployed without
repackaging the game.
